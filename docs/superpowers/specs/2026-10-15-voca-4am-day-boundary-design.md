# 보카 탭: 오전 4시 학습일 경계 설계

## 목표
보카 탭의 "복습할 표현 / 새 표현"이 매일 **오전 4시(기기 로컬 시각)** 에 갱신된다.

- 하루 집계(새 표현 일일 한도, 학습 기록, 스트릭, 달력, 주간 XP)가 04:00에 넘어간다. 00:00–03:59 학습은 전날로 집계된다.
- 1일 이상 간격의 복습 카드는 해당 학습일 04:00에 한꺼번에 열린다.

범위: 보카 탭만. 영상 단어장(`SRS_DAYS`, `calcStreak`) 등 다른 탭은 그대로 둔다.

## 결정: 저장 시점에 맞춤 (B안)
`vkReview`가 `due`를 계산할 때 04:00 경계로 맞춰 저장한다. 판정 로직(`dueKeys`)은 `due <= now` 그대로 둔다.

- 이미 저장된 카드는 마이그레이션하지 않는다. 다음 복습 전까지 기존 `due`(정확한 시각)대로 열리고, 한 번 복습하면 새 규칙을 따른다.
- 저장 형식(`st.srs[key]`)은 바뀌지 않으므로 Supabase 동기화·`vkMergeState`에 영향이 없다.

## 변경 사항 (`index.html`, VOCA-TESTABLE 블록)

1. `VK_DAY_START_H = 4` 상수 추가.
2. `vkDayStart(ts)` 추가: `ts`가 속한 학습일의 04:00 타임스탬프.
   `new Date(ts - 4h)`의 날짜에 `setHours(4,0,0,0)`.
3. `vkDay(ts)`: `ts - 4h`의 로컬 날짜(`YYYY-MM-DD`)를 돌려준다.
   `todayKey`, `dayRec`, `newLeftToday`, `vkStreak`, 달력·리포트가 모두 이를 거치므로 자동 반영된다.
4. `vkWeekStart(ts)`: 월요일 **04:00** 을 돌려준다(`vkDayStart` 기준으로 요일 계산).
5. `vkReview`: 단계 `s >= 1`이면
   `r.due = vkAddDays(vkDayStart(now), VK_STEPS[r.s] / VK_DAY)` — "N일 = N번째 다음 학습일 04:00".
   `s = 0`(5분)은 기존대로 `now + 5분`.
   - 예: 23:00에 푼 "1일" 카드 → 다음 날 04:00. 02:00에 푼 "1일" 카드(전날 학습일) → 같은 날 04:00.
6. UI(`fillTabHTML`): "내일까지" 예보 경계를 `vkAddDays(vkDayStart(now), 2)`로 변경.
7. 주간 막대 요일 라벨(약 4059행): `new Date(t).getDay()` 대신 학습일 키(`k`)에서 요일을 구해, 새벽에도 라벨과 날짜가 일치하게 한다.

## 기존 데이터
- `st.log`의 과거 키는 그대로 둔다(과거 00:00–03:59 기록은 달력 날짜 기준으로 남음).
- 기존 카드 `due`는 그대로 — 다음 복습 시 새 규칙으로 바뀐다.

## 테스트 (`tests/voca-core.test.mjs`)
- `vkDay`: 같은 날짜 03:59 → 전날, 04:00 → 당일.
- `vkDayStart`: 02:00 → 전날 04:00, 15:00 → 당일 04:00.
- `vkWeekStart`: 월요일 04:00(기존 "월요일 0시" 테스트 수정), 월요일 02:00은 직전 주로.
- `vkReview`: "1일" 단계가 23:00 → 다음 날 04:00, 02:00 → 당일 04:00. "3일" 단계는 3번째 다음 학습일 04:00. 5분 단계는 정확히 `now + 5분`.
- 기존 `vkReview` 단계 테스트(now=0 사용)는 `due` 값을 단정하지 않으므로 그대로 통과해야 한다.
